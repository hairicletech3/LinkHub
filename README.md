# Ancle Hai Hotpot — LinkHub

A single-page "link in bio" site for **Ancle Hai Hotpot** (Phnom Penh) — the page customers land on from social bios and printed QR codes to follow, join, contact, or find a branch.

No framework: plain HTML + vanilla JS, styled with Tailwind CSS (compiled ahead of time, not the CDN build). Deployed on Vercel.

## Stack

- **HTML/CSS/JS** — static, no build framework or bundler
- **Tailwind CSS** — compiled via the Tailwind CLI (`src/input.css` → `src/output.css`)
- **[lucide](https://lucide.dev/) icons** — loaded from a CDN `<script>`, deferred so it never blocks first paint
- **live-server** — local dev server with auto-reload
- **Vercel** — hosting/deploy (`vercel.json`)

## Project structure

```
src/
  index.html      # the whole page markup
  main.js         # all page behavior (see below)
  input.css       # Tailwind entrypoint + hand-written CSS (source of truth)
  output.css      # compiled CSS — gitignored, generated by `npm run build`
  assets/
    ANCLEHAI_LOGO_REVERSE.jpg
    branch{1-4}.jpg          # original shopfront photos, one per branch
    branch{1-4}-640.jpg      # pre-resized + sharpened, for smaller phones
    branch{1-4}-960.jpg      # pre-resized + sharpened, for larger/high-DPI phones
```

`output.css` is intentionally **not** committed — it's a build artifact regenerated by `npm run build` (locally and by Vercel on deploy).

## Getting started

```bash
npm install
npm run dev
```

`dev` runs two things at once: a Tailwind watcher (rebuilds `output.css` on every `input.css` change) and `live-server` on `src/` at `http://localhost:3000`, which auto-reloads the browser on any file change.

### Other scripts

| Command | What it does |
|---|---|
| `npm run build` | One-off production build of `output.css` (minified) — what Vercel runs on deploy |
| `npm run watch:css` | Tailwind watcher only, no dev server |
| `npm run serve` | live-server only, no CSS watcher (use if you're editing `output.css` output directly or it's already built) |

## What's on the page

Top to bottom:

1. **Marquee** — scrolling strip of taglines, looped seamlessly by JS measuring its own width.
2. **Hero** — logo with a breathing glow ring, headline.
3. **Link cards** (the main funnel):
   - **Follow us** → TikTok
   - **Join our Channel** → Telegram
   - **Get directions** → expands into a branch picker: tabs for each location, a shopfront photo, address, and an "Open in Google Maps" button. State-driven, not separate pages.
4. **Also find us** — a compact icon grid for secondary links (Facebook, Instagram, Contact us). Tiles render faded/dashed at rest and come forward (solid border, full opacity, orange glow) on hover, focus, or tap.
5. **Footer**.

Two features exist in the code but are **commented out** (deliberately, with instructions inline for how to bring them back): "Rate us on Google" (a 3rd funnel card) and a radial orbital timeline. Removing the HTML comment wrapper around either is enough — the CSS/JS is already wired up.

### Ambient glow

Every interactive element (`.card`, `.social-tile`, `.map-cta`, the open "Get directions" drawer) has two layers of the same accent glow:
- **Idle**: a slow, staggered breathing pulse (`@keyframes ambient-glow`) so the page feels alive without any interaction.
- **Active**: a stronger, static glow + lift on hover/focus/press, which cancels the idle animation while it's showing.

Respects `prefers-reduced-motion`.

## Customizing content

Everything content-specific lives in `src/main.js`, near the top of each section:

- **`SOCIALS`** — the "Also find us" grid. Each entry is `{ name, icon, url }`. An icon must exist in `BRAND_ICONS` (`tiktok`, `telegram`, `facebook`, `instagram`, `youtube`, `whatsapp`, `phone`). A tile whose `url` still starts with `REPLACE_WITH...` renders greyed out and inert instead of a dead link — fill it in and it goes live automatically.
- **`BRANCHES`** — one entry per location, each with:
  - `photo` — shopfront image path in `src/assets/`. For a new branch photo, generate `-640`/`-960` sharpened variants (see below) alongside the original so it loads crisp on phones without shipping one huge file.
  - `maps` — Google Maps share link (required)
  - `review` — direct "leave a review" link (optional; falls back to `maps` until set)
  - `coords` — `lat,lng`, strongly recommended so the map preview pins the right spot
  - `area` / `address` — short label vs. full address shown under the photo
- **Contact number** — the "Contact us" tile in `SOCIALS` uses a `tel:` URL directly.

A URL like `?b=vanda` deep-links straight to a given branch's directions/tabs — handy for printing a different QR code per location.

### Generating responsive branch photos

Branch photos are served via `srcset` (`-640`, `-960`, and the original as the largest candidate) so phones never have to downscale one huge image live — that's what caused a "low resolution" look before this was added. To regenerate variants after replacing a photo:

```bash
npx sharp-cli -i src/assets/branchN.jpg -o /some/tmp/dir -q 82 resize 640 -- sharpen 1
npx sharp-cli -i src/assets/branchN.jpg -o /some/tmp/dir -q 82 resize 960 -- sharpen 1
# then move/rename the outputs to src/assets/branchN-640.jpg and branchN-960.jpg
```

(Resize to a temp directory first, not straight into `src/assets/` with the same filename — `sharp-cli` names output files after the input, so resizing twice into the same folder overwrites the original.)

| Token | Value | Use |

## Deployment

Hosted on Vercel (`vercel.json`): build command `npm run build`, output directory `src`. Pushing to the connected branch triggers a rebuild — `output.css` doesn't need to be committed, Vercel generates it fresh from `input.css` on every deploy.
